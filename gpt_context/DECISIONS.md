## 2026-10-09 — Единая кодовая база для Windows 10 и Unix

Newsbot и планируемый веб-интерфейс должны поддерживать Windows 10 и Unix (прежде всего Debian Linux и FreeBSD) из одной кодовой базы. Разработка ведётся на Windows 10 с Python 3.13; совместимость с Unix предстоит проверить на целевых системах.

**Почему:** разработка выполняется на Windows, а развёртывание возможно на Unix. Поддерживать отдельные варианты приложения для каждой ОС нецелесообразно.

**Последствия:**

- Сохранять общую логику обработки писем, VK и WordPress независимой от ОС; использовать кроссплатформенные пути и файловые операции.
- Устанавливать Python-зависимости и внешний Pandoc отдельно для каждой целевой платформы.
- Настраивать запуск по расписанию вне основного Python-кода: Планировщик заданий Windows или cron на Unix (планируемый интервал — раз в 2 часа).
- Проектировать будущий веб-интерфейс с тем же требованием совместимости, пока без обязательного выбора веб-фреймворка.
- Предпочитать небольшие адресные правки, а не рефакторинг ради кроссплатформенности; до развёртывания подтвердить работу на Unix тестами.

## 2026-10-10 — Управление автоматическим запуском через файл-флажок на Unix

На Debian Linux и FreeBSD плановый запуск `main.py` остаётся во внешнем `cron` (ориентировочно раз в 2 часа). Задание cron не редактируется при обычном включении или остановке Newsbot. Вместо этого запускающий POSIX shell-скрипт перед вызовом Python проверяет файл `.newsbot.disabled` в каталоге проекта:

- Файл отсутствует — запуск разрешён; shell-скрипт запускает `main.py`.
- Файл существует — запуск пропускается с успешным завершением shell-скрипта.
- Кнопка остановки в WebUI создаёт этот файл; кнопка запуска удаляет его. Наличие и изменение файла должны проверяться с учётом прав доступа и возможных ошибок файловой системы.

**Почему:** не требуется изменять `main.py` и `config.py` ради переключателя, а также перезаписывать crontab. Работает одинаково на целевых Unix-платформах и позволяет сохранить WebUI независимым от конвейера обработки писем.

**Последствия:**

- «Запущен» означает, что автоматические запуски разрешены, а не то, что процесс `main.py` прямо сейчас выполняется. Для достоверного статуса WebUI дополнительно должен проверять наличие ожидаемого cron-задания; наличие записи в crontab само по себе не гарантирует исправность cron.
- «Остановлен» запрещает **следующие** плановые запуски; уже работающий экземпляр `main.py` не прерывается. Существующий process lock продолжает защищать от параллельной обработки.
- WebUI и cron-скрипт должны работать с одним и тем же абсолютным путём к `.newsbot.disabled`. Нужны минимально необходимые права доступа; пользователь WebUI не должен получать доступ к управлению чужими задачами cron.
- На Windows взаимодействие WebUI с Планировщиком заданий не реализуется; отображается `Windows/manual`. Проверка файла-флажка применяется только в Unix-обёртке запуска.
- Реализация и проверка поведения на Debian/FreeBSD остаются отдельным этапом; до этого запись фиксирует принятое проектное решение, но не подтверждает внедрение.
