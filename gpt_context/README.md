# VKTest: контекст проекта

## 1. Цель проекта

**VKTest** — Python-проект для автоматизации подготовки и публикации новостей из входящих писем в WordPress с использованием данных и медиаматериалов из VK.

Основной сценарий:

1. Найти одно непрочитанное письмо.
2. Скачать письмо в формате `.eml`.
3. Распарсить содержимое письма.
4. Извлечь текст новости, ссылки и изображения.
5. Найти в содержимом ссылки/идентификаторы объектов VK, в том числе вложенные.
6. При наличии видео получить через VK API необходимые данные для формирования embed-кода и preview-изображения.
7. Сформировать итоговую публикацию.
8. Передать её в WordPress.
9. После обработки удалить временный `.eml` и извлечённые изображения.
10. Продолжить обработку следующего письма даже если обработка одной новости завершилась ошибкой.

Проект развивается как набор небольших Python-модулей, каждый из которых отвечает за отдельную часть конвейера.

---

## 2. Общая архитектура

Упрощённая схема текущего конвейера:

```text
Почтовый ящик
     │
     ▼
   main.py
     │
     ├── получение одного непрочитанного письма
     │
     ▼
  downloaded_eml/
     │
     ▼
 eml_parser.py
     │
     ├── разбор .eml
     ├── извлечение текста
     └── извлечение вложений/изображений
     │
     ▼
 eml_links.py
     │
     ├── поиск ссылок
     ├── поиск VK wall/video и других идентификаторов
     └── обработка ссылок в HTML/тексте
     │
     ▼
 VK API / VK-модули
     │
     ├── получение информации о VK-объектах
     ├── поиск видео
     ├── получение embed-данных
     └── получение preview
     │
     ▼
 Формирование WordPress-контента
     │
     ▼
 WordPress API
     │
     ▼
 Публикация новости
     │
     ▼
 finally:
 ├── удаление обработанного .eml
 └── очистка extracted_images/
```

Архитектура постепенно разделяется на независимые этапы: получение письма → парсинг → извлечение ссылок/медиа → работа с VK → подготовка WordPress-контента → публикация.

Важный принцип текущей обработки: **ошибка при обработке одной новости не должна останавливать весь цикл**. Исключение должно быть обработано на уровне одной итерации, после чего временные файлы очищаются в `finally`, а цикл переходит к следующему письму.

## 3. Основные модули

### `main.py`

Главная точка входа проекта и координатор всего конвейера.

Отвечает за:

* запуск основного цикла;
* поиск/получение одного непрочитанного письма;
* сохранение письма в `downloaded_eml/`;
* последовательный запуск существующего pipeline;
* обработку ошибок отдельной новости;
* гарантированную очистку временных файлов через `finally`;
* переход к следующему письму после ошибки.

Текущая логика предполагает примерно такую структуру:

```text
while есть непрочитанные письма:
    скачать ОДНО письмо
    try:
        обработать новость
    except:
        зафиксировать ошибку
    finally:
        удалить .eml
        очистить extracted_images
```

То есть `main.py` является orchestration-слоем, а основная бизнес-логика вынесена в специализированные модули.

---

### `eml_parser.py`

Модуль разбора `.eml`.

Использует стандартный Python-модуль `email` и отвечает за извлечение содержимого письма.

Основные задачи:

* открыть `.eml`;
* разобрать MIME-структуру;
* найти HTML/plain-text части;
* извлечь текст;
* обработать вложения;
* извлечь изображения во временную директорию `extracted_images/`.

Модуль не должен отвечать за публикацию в WordPress или работу с VK, его задача заключается именно в преобразовании почтового сообщения в пригодные для дальнейшей обработки данные.

---

### `eml_links.py`

Модуль обработки ссылок, найденных в содержимом письма.

Основные задачи:

* поиск URL в тексте/HTML;
* обработка ссылок внутри фрагментов письма;
* поиск VK-идентификаторов;
* распознавание конструкций вида:

```text
wall-188414783_53864
```

* подготовка найденных ссылок/идентификаторов для последующей обработки VK-модулями.

Особенно важно, что поиск VK-объектов должен учитывать не только обычные ссылки, но и ссылки/объекты, находящиеся внутри вложенных HTML-фрагментов и аттачей.

---

### VK API / обработка VK-видео

Отдельная часть проекта отвечает за работу с VK API.

В текущей разработке реализовывалась обработка VK-видео, найденных в ссылках/аттачах.

Для видео необходимо:

1. определить `owner_id` и `video_id`;
2. обратиться к VK API;
3. получить информацию о видео;
4. получить данные, необходимые для формирования HTML embed;
5. получить preview-изображение;
6. использовать preview в требуемом разрешении, в частности рассматривалось разрешение `width: 720`.

Для поиска видео учитываются **рекурсивные вложения (`attachments`)**, поскольку VK-объект может находиться не только на верхнем уровне структуры.

---

### WordPress-модуль / WordPress API

Отвечает за взаимодействие с WordPress.

Основные задачи:

* проверка доступности WordPress API;
* подготовка данных публикации;
* передача текста и медиаматериалов;
* создание/размещение новости;
* работа с необходимыми WordPress endpoint'ами.

В процессе разработки отдельно использовался `wp_probe.py` для проверки доступности и поведения WordPress API.

---

### `wp_probe.py`

Вспомогательный диагностический скрипт.

Используется не как основной production pipeline, а для проверки WordPress API и отдельных запросов.

Помогал при первоначальной проверке:

* доступности WordPress;
* авторизации;
* структуры ответов API;
* корректности endpoint'ов.

---

### `config.py`

Конфигурация проекта.

Содержит настройки, которые не должны быть жёстко зашиты в бизнес-логику модулей.

В проекте отдельно обсуждалась необходимость шаблонного `config.example.py`, чтобы структура необходимых настроек была понятна при переносе проекта, но реальные секреты и локальные параметры не должны попадать в Git.

---

### `downloaded_eml/`

Временная директория для скачанных писем.

Используется как промежуточное хранилище:

```text
почта → downloaded_eml/*.eml → обработка → удаление
```

После завершения обработки конкретного письма файл `.eml` должен удаляться независимо от того, завершилась обработка успешно или с ошибкой.

---

### `extracted_images/`

Временное хранилище изображений, извлечённых из `.eml`.

Используется во время обработки новости.

После завершения обработки текущей новости директория должна очищаться, в том числе при возникновении исключения.

---

## 4. Конфигурация и зависимости

Проект написан на Python.

Текущее окружение разработки:

```text
Python 3.13.15
pip 26.2.1
```

Работа ведётся в Windows.

Исходный проект переносился в GitHub и используется Git как основная система контроля версий.

В проекте используются внешние Python-библиотеки, в частности `requests`, а также стандартные библиотеки Python для работы с MIME/HTML/файлами.

Конфигурационные и секретные данные должны быть отделены от исходного кода и исключены из Git через `.gitignore`.

## 5. Git и контекст для ChatGPT

**Исходники проекта находятся в публичном Git-репозитории:**

https://github.com/Ed1ch/VKtest

При работе с проектом в первую очередь следует ориентироваться на актуальное содержимое Git-репозитория, а не на предположения о состоянии исходников из старых сообщений.

Отдельно в репозитории существует директория:

```text
gpt_context/
```

В ней находятся `.md`-файлы с контекстом, предназначенные именно для работы ChatGPT с проектом.

Эти файлы следует рассматривать как дополнительную документацию/контекст проекта. При необходимости восстановления истории решений сначала нужно проверить `gpt_context/`, а затем актуальные исходники.

## 6. Текущее состояние проекта

Проект находится **в активной разработке**, но уже имеет рабочие части pipeline.

На текущем этапе:

* проект перенесён в GitHub;
* используется Git для контроля исходников;
* Python и pip установлены;
* проект запускается из Windows;
* базовый pipeline обработки `.eml` уже существует;
* реализована/разрабатывается обработка ссылок из `.eml`;
* VK-объекты ищутся в структуре содержимого;
* обработка VK-видео развивается в сторону рекурсивного поиска по `attachments`;
* для VK-видео реализуется получение данных через VK API для последующего формирования embed;
* отдельно решается получение preview-изображения VK-видео в требуемом размере;
* WordPress API уже проверялся отдельными диагностическими запросами;
* предусмотрена очистка временных файлов после обработки;
* сейчас важна устойчивость основного цикла: **ошибка одной новости не должна прекращать обработку остальных писем**.

Последнее состояние архитектуры следует считать промежуточным: проект ещё рефакторится, поэтому перед изменением конкретного модуля необходимо посмотреть его актуальную версию в GitHub и, при наличии, соответствующий `.md`-контекст в `gpt_context/`.
